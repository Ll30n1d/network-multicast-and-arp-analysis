## Цель проекта

Изучить принципы multicast-взаимодействия и разрешения IP-адресов в MAC-адреса с использованием протоколов ICMP и ARP. Получить практический опыт захвата и анализа сетевого трафика, а также изучить применение статических ARP-записей в качестве ограниченной меры защиты.

В рамках проекта исследованы multicast ICMP-запросы, механизм ARP Request/Reply и работа статических ARP-записей.

## Контекст

Для моделирования сетевого взаимодействия использовалась виртуальная лаборатория GNS3 с двумя маршрутизаторами Cisco 3745, соединёнными напрямую.

## Окружение и инструменты

| Компонент | Назначение |
|---|---|
| GNS3 | Эмуляция сетевой инфраструктуры |
| Cisco 3745 | Сетевые маршрутизаторы |
| Cisco IOS CLI | Настройка сетевых интерфейсов и протоколов |
| Wireshark | Захват и анализ сетевого трафика |
| PCAP | Сохранение результатов захвата сетевого трафика |

## Ход работы

> Подробный отчёт (конфигурации, результаты проверок, анализ пакетов и скриншоты): [docs/report.md](docs/report.md)

### 1. Multicast-запросы

Создана лабораторная топология из двух маршрутизаторов Cisco 3745. Настроены сетевые интерфейсы и IP-адресация.

На одном из маршрутизаторов настроено членство интерфейса в multicast-группе `239.1.1.1`.

С помощью ICMP выполнена проверка multicast-взаимодействия. В Wireshark исследованы Ethernet-, IP- и ICMP-заголовки, включая MAC-адрес назначения multicast-пакета.

### 2. ARP

Исследован механизм определения MAC-адреса по известному IP-адресу.

После очистки ARP-кэша выполнен ping между маршрутизаторами. В Wireshark проанализированы ARP Request и ARP Reply, а также соответствующие ICMP-пакеты.

Проверена ARP-таблица и изучены MAC-адреса отправителя и получателя в ARP-сообщениях.

### 3. Static ARP

В качестве дополнительной практической части настроена статическая ARP-запись для IP-адреса соседнего маршрутизатора.

Проверено соответствие IP- и MAC-адресов, выполнен ping после настройки и исследован сетевой трафик в Wireshark.

Сравнено поведение ARP до и после добавления статической записи: при наличии заранее заданного соответствия новый ARP Request для этого адреса не потребовался.

## Анализ сетевого трафика и применение в SOC

Понимание нормального поведения сетевых протоколов помогает анализировать сетевые события и выявлять отклонения от ожидаемой активности.

В проекте исследованы следующие особенности сетевого взаимодействия:

| Протокол / механизм | Изучаемые особенности |
|---|---|
| Multicast | Передача трафика группе получателей |
| Ethernet | MAC-адреса источника и назначения |
| IPv4 | Адресация multicast-пакетов |
| ICMP | Echo Request и Echo Reply |
| ARP | Разрешение IP-адресов в MAC-адреса |
| Static ARP | Фиксированное соответствие IP–MAC |

Отдельное внимание уделено безопасности ARP. Подмена ARP-записей (ARP-spoofing) может использоваться для создания условий проведения атак Man-in-the-Middle (MITM).

Статические ARP-записи позволяют закрепить соответствие IP–MAC на отдельном устройстве, однако не обеспечивают полноценную защиту всей сети от ARP-spoofing.

Практическая реализация ARP-spoofing и MITM в рамках проекта не выполнялась.

- Проанализированы Ethernet-, IP- и ICMP-заголовки multicast-пакетов.
- Исследованы ARP Request и ARP Reply.
- Проверена работа ARP-таблицы после сетевого взаимодействия.
- Настроена статическая ARP-запись и проверена её работа.
- Сравнено поведение ARP до и после настройки статического соответствия.
- Сетевой трафик сохранён в PCAP-файлах и проанализирован в Wireshark.
- Результаты лабораторной работы сохранены в виде проекта GNS3, PCAP-дампов и скриншотов.
